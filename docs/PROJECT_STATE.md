Why one commit instead of the earlier C1–C4 split: `npm run knowledge:check` is a whole-tree generated-artifact gate — `build-system-docs.mjs` regenerates `docs/SYSTEM_REFERENCE.md` from every public RPC across the migration set, and `build-knowledge-seed.mjs` byte-compares the committed reseed migration to the regenerated corpus from the tracked markdown. Any intermediate commit that adds migrations (C1–C3) without the regenerated `SYSTEM_REFERENCE`/reseed (C4) is provably red, and fabricating intermediate reseed migrations would corrupt the real 42-applied/15-pending ledger. Combining the dependent changes into one atomic commit is the only structure where every commit passes all required CI checks (explicitly authorized by the commit instruction to prefer this over knowingly-broken intermediate commits). The `src/types/index.ts` mixed-hunk concern is therefore moot: `Profile.purged_at`, `Expense/Sale.updated_at`, and the `customer` citation type all land atomically with `CitationLinks`/`CopilotPage`, so no commit ever has a type/consumer mismatch (TS2741).

## Vehicle field purge + "Loại xe" catalogue — 2026-10-08

Per the shop owner's decision, six specification fields are gone from the product permanently. Forward-only migration `20261008000300_vehicle_type_catalog_and_purge.sql` (LOCAL/PENDING, not deployed) drops `vehicles.brand`, `model`, `variant`, `engine_number`, `odometer` and `asking_price` with `CASCADE`, and replaces `model` with `vehicle_type_id uuid NOT NULL REFERENCES public.vehicle_types(id)`. No legacy value is mapped: every existing vehicle lands in the protected `Chưa phân loại` row and staff reclassify per record when they next open the file. The new `public.vehicle_types` catalogue (unique index on `lower(btrim(name))`, `CHECK char_length 2..60`, RLS `SELECT`-only for the client) is maintained by OWNER under Cài đặt → **Loại xe** through `save_vehicle_type`/`delete_vehicle_type` (`DUPLICATE_VEHICLE_TYPE`, `VEHICLE_TYPE_IN_USE`, `VEHICLE_TYPE_PROTECTED`), read by everyone active through `list_vehicle_types`, and adding a type needs no migration. Identity is now one shared helper on both sides: title **biển số · số khung** (`private.vehicle_label_text` / `src/lib/vehicleDisplay.ts`), subtitle **loại xe · đời · màu** (`private.vehicle_subtitle_text` / `vehicleSubtitle`), used by lists, detail, receipts, notifications, search, copilot and the public showroom. `sale_price` has no server-side source any more — it originates only from the Bán xe form, is never prefilled, and the public showroom shows no price at all (the customer "Định giá xe cần bán" field stays because `expected_price` is customer-declared). All rows in `audit_logs`, `vehicle_activity`, `notifications`, `customer_communications` and `message_outbox` are deleted (no tombstone), with the two immutability triggers suspended for that single statement; business and financial tables and the immutable `sale_financials` profit snapshot are untouched. Every read/write RPC that referenced a dropped column was rebuilt in the same migration, and the migration ends with a `DO` block that fails the transaction if a column, a history row, an untyped vehicle, the old index, or a `pg_proc` body still mentioning a purged field survives. Docs, the `ai-assist` contract (the `odometer` task is deleted; camera/voice/OCR return plate/frame/color/year only), the shorthand vocabulary (unknown tokens no longer fall into a model line), and the draft keys (`xe_crm_draft_v2`, `xe_crm_ux_v3`, deliberately invalidating old drafts) were updated in the same pass. `docs/VEHICLE_FIELD_PURGE_IMPACT.md` carries the dependency inventory, row-loss counts and the copies that cannot be erased.
