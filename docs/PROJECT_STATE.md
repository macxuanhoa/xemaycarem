## Shorthand intake (/intake) — 2026-10-02

The learned dictionary is per device/account and is not synced to the server; no migration or Edge Function changed.

## No forced first-login password change — 2026-10-02

Per the shop owner's request, newly created staff accounts sign straight into the app: the `manage-users` Edge Function `create` action no longer sets `must_change_password`, so the `/change-password` interstitial never appears for provisioning. Forward-only migration `20261002003500_no_forced_first_password_change.sql` releases accounts still gated by the old rule while keeping pending administrative resets (`reset_pending`) fail-closed, momentarily suspending `protect_last_usable_owner` around that single UPDATE. The mechanism remains active for the explicit OWNER action `reset_password` (the `force_password_change` action was later removed — see **Staff management** below), and staff who want a new password self-serve in Cài đặt → Đổi mật khẩu. Create-user dialog copy updated accordingly. Local gates: lint, typecheck, vitest, DB suite (migration replay on a disposable DB), regenerated knowledge seed.

## Staff management: shared schedule, single owner, bounded ban — 2026-10-02

The staff area was reworked per the shop owner's request. The staff detail modal is fixed on mobile (bottom sheet fitting a 390×844 viewport, tabs **Quyền & Vai trò** / **Bảo mật & Trạng thái**, no horizontal overflow; Playwright asserts bounding box and `scrollWidth`). Per-account working hours were deleted as a concept: the profile columns `allowed_from/allowed_until/working_days` are legacy and no longer read for access, replaced by one shared schedule on `system_settings` (`staff_allowed_from/staff_allowed_until/staff_working_days`) applied to every non-OWNER role, overnight-window aware, Asia/Ho_Chi_Minh; OWNER-only to write via `save_settings` with server-side validation (`INVALID_SCHEDULE`). Account security offers exactly two modes: delete account (history kept; the final active OWNER cannot be deleted) and a bounded temporary ban (`disable` requires a future `disabledUntil`; presets Hết hôm nay / 7 ngày / 30 ngày / custom) — the require-new-password, unlimited lock, and old disable actions were removed and now return `INVALID_ACTION` from `manage-users`. Role hierarchy: exactly one active OWNER (raw second-owner writes hit `SINGLE_OWNER_REQUIRED`; promotion goes only through the atomic `transfer_ownership` RPC, serialized with `update_profile` on advisory lock 761482190, refusing self-transfer and inactive targets); MANAGER may change roles of juniors (STAFF) only; STAFF has no staff-management rights and `/users` moved to `access="manage"`. The "owner has the highest full control" wording was removed from the UI. Forward-only migration `20261002003600_shared_schedule_and_single_owner.sql` (renumbered from `003500` due to a version collision with the first-login migration) is APPLIED on production per the 2026-10-03 verified ledger. Local gates recorded in `docs/VERIFICATION.md`.
