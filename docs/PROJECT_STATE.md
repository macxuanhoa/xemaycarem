## Release-candidate verification and local commit — 2026-10-06

After the concurrent Copilot writer was confirmed stopped by process ownership (zero Codex/node/deno writer processes; newest dirty write frozen 17:31:13 across repeated watchdog samples; final Git status drift 0), the full 119-file workspace (64 modified + 55 untracked) was independently re-verified as one coherent snapshot and committed locally as a **single atomic commit** on `release/xe-crm-v1`.

Why one commit instead of the earlier C1–C4 split: `npm run knowledge:check` is a whole-tree generated-artifact gate — `build-system-docs.mjs` regenerates `docs/SYSTEM_REFERENCE.md` from every public RPC across the migration set, and `build-knowledge-seed.mjs` byte-compares the committed reseed migration to the regenerated corpus from the tracked markdown. Any intermediate commit that adds migrations (C1–C3) without the regenerated `SYSTEM_REFERENCE`/reseed (C4) is provably red, and fabricating intermediate reseed migrations would corrupt the real 42-applied/15-pending ledger. Combining the dependent changes into one atomic commit is the only structure where every commit passes all required CI checks (explicitly authorized by the commit instruction to prefer this over knowingly-broken intermediate commits). The `src/types/index.ts` mixed-hunk concern is therefore moot: `Profile.purged_at`, `Expense/Sale.updated_at`, and the `customer` citation type all land atomically with `CitationLinks`/`CopilotPage`, so no commit ever has a type/consumer mismatch (TS2741).
